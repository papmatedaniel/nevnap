API paraméterének vizsgálata (Változatok), akár handlerben is
A) A "Modern PHP" (Null Coalescing operátor)
A ?? operátorral alapértelmezett értéket adunk a változónak, ha az hiányzik.
Használata: Amikor mindenképpen változóba akarjuk menteni az adatot, hibaüzenetek elkerülésével.
Példa: Opcionális beállítások (pl. nyelvválasztás, rendezési szempont).

röviden:
változóba akarod menteni a bemenetet
és nem tudod, hogy létezik-e
és később többször használod

$nev = $_GET["nev"] ?? null;
$datum = $_GET["datum"] ?? null;

if ($nev === null && $datum === null) { /* Hiba: nincs paraméter */ }
elseif ($nev !== null && $datum !== null) { /* Hiba: túl sok paraméter */ }
elseif ($nev !== null) { /* Keresés név alapján */ }
elseif ($datum !== null) { /* Keresés dátum alapján */ }
Figyelem: Az üres stringet (?nev=) átengedi, mert az nem null!


B) Az "Alap" (Hagyományos isset)
A klasszikus módszer, ami csak a létezést ellenőrzi.
Használata: Checkboxoknál, gomboknál, vagy ahol a 0 is érvényes adat (pl. pontszám).
Példa: if (isset($_POST['mentes_gomb'])) { ... }

if (!isset($_GET["nev"]) && !isset($_GET["datum"])) { ... }
elseif (isset($_GET["nev"]) && isset($_GET["datum"])) { ... }
elseif (isset($_GET["nev"])) {
    $nev = $_GET["nev"];
}
elseif (isset($_GET["datum"])) {
    $datum = $_GET["datum"];
}


C) A "Flag-es" megoldás
Logikai segédváltozókat (igaz/hamis) használunk az átláthatóságért.
Használata: Bonyolultabb feltételeknél, hogy ne legyen túl hosszú az if sora.
Példa: Jogosultságok és állapotok együttes vizsgálata.

$nap_set = isset($_GET['nap']);
$nev_set = isset($_GET['nev']);

if ($nap_set && $nev_set) { ... } // Mindkettő be van állítva
if (!$nap_set && !$nev_set) { ... } // Egyik sem

if ($nap_set) {
    $datum = $_GET["nap"];
} else {
    $nev = $_GET["nev"];
}


D) A "Svájci Bicska" (!empty) – LEGJOBB SZÖVEGES BACKENDHEZ, APIHOZ
Egyszerre nézi, hogy létezik-e a paraméter ÉS van-e benne tartalom.
Használata: Szöveges keresésnél (név, dátum, email), ahol az üres mező nem adat.
Példa: Keresőmezők, kötelezően kitöltendő szöveges adatok.

if (!empty($_GET['nev'])) {
    // Csak akkor fut le, ha a kulcs létezik ÉS nem üres string ("")
    $nev = $_GET['nev'];
} 
elseif (!empty($_GET['nap'])) {
    $nap = $_GET['nap'];
} 
else {
    // Üresen hagyott mezők vagy hiányzó paraméterek
}


E) A "Lusta Profi" (Rövidített kiértékelés)
Kombinálja az alapértelmezett értéket a PHP logikai rugalmasságával.
Használata: Gyors szűrésre SQL lekérdezések előtt.
Példa: API kereső funkció.

$nev = $_GET['nev'] ?? ""; // Ha hiányzik, legyen üres string

if ($nev) { 
    // Mivel az üres string "" logikailag FALSE, ez csak akkor 
    // igaz, ha van benne érdemi tartalom.
    $tisztitott_nev = mysqli_real_escape_string($db, $nev);
}



Gyors döntési segédlet:
Szöveget (név, dátum) vársz? → Használd a D vagy E verziót (!empty), hogy kiszűrd az üresen küldött kereséseket.
Számot vársz (ahol a 0 is érték)? → Használd az A vagy B verziót (isset), mert az empty a nullát is hibának látná.
Gombot vagy checkboxot vizsgálsz? → Használd a B verziót (isset).

7. GET és POST közötti különbségek.

A) $_GET szuperglobális változó

    Hogyan működik? AZ adatokat az URL címen keresztül küldi el a szervernek. Pl index.phpnev=Mate&na=05-16
    Hogyan tárolódik le? A PHP automatikusan egy asszociatív tömbbe(szótárba) tpakolja az URL-be kapott kulcs-érték     párokat, amit a $GET globális tömbbel érhetsz el, pl $_GET["nev"]



    Mikor használjuk?:
        - Adatok lekérésére, keresésre, szűrésre
        - API-k esetében a végontok paraméterezésére.
        - Könyvjelzőknél(mivel a paraméterek benne maradnak a linkben)

   Hátránya: Nem biztonságos szenzitív adatokra (jelszó, bankkártya), mert az adatok látszódnak a böngészési előzményekben és a szervernaplókban. Az URL hossza ráadásul korlátozott (böngészőtől függően kb. 2000 karakter).

    

B) $_POST szuperglobális változó

    Hogyan működik? AZ adatokat, rejtve a HTTP kérés törzsében (body) küldi el. Az URL-ben semmi sem látszódik belőle.
    Hogyan tárolódik le? A PHP a háttérben érkező adatokat a $_POST asszociatív tömbbe helyezi el pl $POST["nev"]

    Mikor használjuk?
        - Adatok létrehozásakor, módosításakor, törlésekor pl regisztráció, bejelentkezés, új fórumposzt, bármilyen <form> adat küldés/feldolgozásnál

        -Fájlok feltöltésekor.
        - Nagy mennyiségű szöveg beküldésénél(nincs szigorú méretkorlát mint a GET-nél)

    Hátránya: Nem lehet közvetlenül könyvjelzőbe menteni az állapotot, és az oldal frissítésekor a böngésző felugró ablakban figyelmzteti a felhasználót az adatok újraküldésére. 




8. SESSIONS kezelés
Állapotmentésre, két egymás utáni oldalletöltésnél a szerver nem tudja, hogy ugyanaz a felhasználó kattint-e. Erre nyújt megoldást a session.

A) Működései elv)
Amikor elindítasz egy session-t, a PHP legenerál egy egyedi azonosítót (Session ID), amit elment a felhasználó böngészőjébe egy sütiben (cookie). A szerver oldalon pedig fenntart egy fájlt ehhez az azonosítóhoz, amiben az adatokat tárolja.


B) Legfontosabb szabályok és függvények

    - Munkamenet indítása:
    session_start();
        FONTOS BACKEND SZABÁLY: Ezt a függvényt minden egyes olyan fájl legtetején meg kell hívni, ahol használni akarod a munkamenet adatait. Semmilyen HTML kód, de még egy üres karakter vagy echo sem előzheti meg, különben hibaüzenetet kapsz!

    - Adat eltárolása és elérése:
    A $_SESSION szintén egy asszociatív tömb, ami az oldal elhagyása vagy bezárása után is megőrzi az értékét:

    $_SESSION["valasz"] = $tomb; // Adat mentése (pl. a handler.php-ban)
    $adat = $_SESSION["valasz"]; // Adat kiolvasása (pl. az index.php-ban)


    - Adat törlése (Unset):
    Ha egy adatot csak egyszer szeretnél megmutatni (például egy sikeres beküldési üzenetet vagy API választ), a kiolvasás után azonnal töröld ki, hogy ne ragadjon be a memóriába a következő oldalfrissítéskor:
    PHP

    unset($_SESSION['valasz']); // Csak ezt a konkrét kulcsot törli


9. A $_SERVER szuperglobális változó

A $_SERVER egy olyan beépített tömb, amit a webszerver (pl. Apache) tölt fel információkkal. A szerver környezetéről, a szkript futási helyéről és a beérkező kérésről ad infót.

    Kérési metódus vizsgálata:
    Gyakran használjuk arra, hogy ellenőrizzük, az űrlap felől érkezett-e a kérés:
    if ($_SERVER["REQUEST_METHOD"] == "POST") {
        // Csak akkor fut le, ha az űrlapot POST-tal küldték be
    }
